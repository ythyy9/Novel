# Novel

以本地项目资料为长期记忆、以可替换 Agent 为执行者、以独立检查和读者反馈为改进依据的小说创作系统。

从参考作品中学习叙事方法，为中国目标读者创造新故事；在人物与世界的因果关系约束下探索后续，逐章写作、审核、研究与返修，并通过有依据的对照改进工作方法。小说、经验、规则和进度属于项目，可以跨对话与执行者延续。

## 架构概要

四层分工：原则与授权、运行控制、创作与研究、项目与经验。

- **作品循环**：恢复人物与世界状态 → 探索下一步 → 写作 → 审核 → 研究或返修 → 阶段性通过 → 更新状态。
- **系统改进循环**：发现重复问题 → 提出原因假设 → 修改方法或工具 → 对照验证 → 保留、暂用或回滚。

两个循环分开运行。正在创作的任务不能通过降低审核标准使当前章节通过。

## 核心约束

- 区分作品已采用事实、人物知识、人物误解、读者知识、作者未决项和未采用候选；重要记录追溯到正文、作者决定或设定依据。
- 人物选择由当时的目标、认识、资源与处境支撑；参考作品提供方法，不决定新故事的路线。《安珀志》仍是候选参考作品。
- 发现知识缺口可以主动研究；记录来源、适用条件、不确定性及影响范围，区分外部事实、系统推断和作品规则，不为既有剧情寻找借口。
- 重要返修同步更新正文、相关状态、受影响章节清单和复核结果；审核结论绑定被审核的版本。
- 交接保存可验证的任务状态、输入版本、改动、未决项与累计重试记录；正式版本实行单写入者，审核可只读。
- 原则、锁定项、原始反馈、基准记录及资源与停止边界不得由当前创作任务自行降低或改写。实际权限隔离完成前，仅能称为流程约束。
- 费用与停止状态跨会话保留；按现有订阅路径规划，不自动切换付费 API、购买额度或通过换会话绕过限制。

## 第一版范围与完成依据

先建设一个本地项目、基础人物与世界记录、可恢复调度、写作与审核任务、按需研究、版本化返修及少量评估案例。按逐章达到阶段性质量要求再推进的方式，用连续几章检验完整流程。

工程检查验证接续、版本、权限和恢复；作者与目标读者的实际阅读反馈检验人物、情感和阅读体验。流程成功、字数、自评分或 Agent 数量不能单独证明作品质量。百万字规模属于可靠流程建立后的远期验证目标。
