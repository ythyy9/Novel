# 真实两端接入清单

离线协议已用合成资料双向验收。真实电脑未连接/操作，未建立共享存储；云端仅保存作者提供的历史第一版，不能以它代替本地第二版。以下是接入步骤，不是已经完成的传输。

## 已有工具可直接做什么

- Git：同步代码、协议与工程进度；不能同步被忽略的作品和runtime。更新本地代码前保留未提交评估文档，不reset或覆盖。
- 本地CLI：audit/handoff/feedback-show/eval-summary核对现有资料；停写后整套备份恢复到独立目录。原副本保留。
- bundle-create/check/receive：显式导出任务与选定资料、校验、保存收件副本、开工门禁。
- bundle-apply：有已验证共同基线时接续一个完成结果为draft。
- bundle-receipt/confirm/ack：核对采用证据、登记同一个新基线，支持下一次反向单任务返修。
- 现有GitHub连接器：只用于开发PR/CI；没有授权把作品或完整原作放入仓库。

## 最少一次需要补齐的信息

1. **一个获准的传输目的地/渠道及双向范围**：指定哪些资料能从本地到云端、哪些可以返回，是否包含原反馈、任务指令、失败事件和评估。不要新增长期凭据或公开分享。尚未授权前仅保留本地文件。
2. **本地第二版及修改依据**：一次性提供第二版、针对名字问题的反馈/修改说明、可定位的book/task/revision或说明它们尚未登记。需要解释生成原因时再附相关提示与上下文；不必重新口述整段历史。引用原作前还需获准使用的相关材料，完整原作不默认传输。
3. **首次共同基线的来源和范围**：确认以哪份本地资料为源。现有单任务包不能凭云端一个历史txt自动重建本地SQLite和版本链。若采用现有停写备份方式，须先批准books/runtime/policies/methods及相关实验的实际内容范围，再在独立资料目录恢复并验证；代码Git同步不等于该步骤。尚无自动最小化数据库迁移工具，不假装只传第二版文本就建立了任务基线。

这三项可一次确认；不要求用户逐项复述创作内容。电脑需上线且有明确授权后才操作本地；当前不访问cc/YT或F:/Novel。

## 接通后的执行顺序

1. 双方保留备份，停写，核对相同代码版本；恢复目录执行audit，并回读实际反馈/实验与任务停止次数。
2. 在明确选择集上导出初始基线，两端bundle-check确认一致；有缺项或冲突即停，不改当前指针。
3. 只在一端执行获准任务；另一端接收完成包，check，再用expected-base/expected-target明确apply。未取得第二版时不续写历史第一版。
4. 交换采用回执及确认，双方登记同一agreement ID；记录各文件哈希、传输结果和登记结果。收件、采用、作者批准分别标记。
5. 从新共同基线验证一次反向接续。缺回执、分叉、停止状态、损坏或目标不符时保存现场，不自动合并或清零。

本清单到资料/目的地授权处停止。没有为了持续运行扩大功能、主动创建存储服务或上传私人作品。
