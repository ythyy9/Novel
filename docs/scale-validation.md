# 有界合成规模与恢复验收

对应路线图阶段 1、2、6，以及 remaining-acceptance 的规模/恢复缺口。源码基线 `6c2fdf739df29f9e00b3adabc3500fd4c4b47ee7`。合成重复字符是存储夹具，不是小说，不调用模型、不读取作者资料。

## 事先定义与复现

Linux、Python 标准库：

```sh
python scripts/validate_scale.py --output .local-validation/scale-new
```

输出目录必须不存在，防止覆盖历史证据。先写 spec.json，再运行隔离工作进程；不会使用现有项目 books/runtime。100 个正文文件，每个恰好 10,000 Unicode 字符（含标记和换行），合计 1,000,000；每批 20 章，共 5 个正常任务，再提交一次改动单章的待发布返修。保持既有单次结果 2 MB 限额，不提高项目控制限额。

上限：工作进程 120 秒，由监督进程管理；512 MiB 地址空间上限继承至 CLI 子进程；开始前要求至少 512 MiB 剩余磁盘。固定数据量及最终资料大小不得超过 256 MiB（这是验收阈值，**不是文件系统硬配额**，没有修改挂载）。超时杀死本次创建的进程组，不触及其他任务。输出 stdout/stderr、执行码、参数、测量值及完整合成资料保留在指定目录。

## 必须通过的检查

- audit 验证源目录 7 个快照（主作品初始 + 5 批、另一本停止夹具初始）、任务关联及哈希。
- 固定版本查询 100 条章节索引，每页 17 条，共 6 页；路径和行号必须恰好匹配全部预期，不漏、不重。
- 全部写入者停止后完整复制到独立目录；新 Engine 和新 CLI 子进程 audit 与源一致，待发布任务交接及另一作品 no_progress 停止记录完全一致。
- 恢复副本发布待提交结果，重复发布幂等；原目录仍 submitted，历史内容未变，文件差异只包含目标章节。
- 在合成恢复副本注入不存在的输入版本引用，audit 必须拒绝；恢复该测试字段后 audit 通过，副本共 8 个快照。
