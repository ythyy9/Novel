## 当前实现

- `novel/dot.py` 复用现有 Engine，提供固定版本任务、分段输入和结果上传、提交、版本发布与阶段验收。没有模型、shell、Codex、Work 或付费 API 调用，也不触发参考书自动刷新。
- `novel/dot_transport.py` 提供7个 MCP 工具定义，要求单独的 `agenthub.novel.runtime` scope、匹配的 owner 和管理员登记的工作区。旧的 `agenthub.novel` 归档权限不能执行这些工具。
- 线上保留独立 `phase=pilot`，另登记正式 `phase=formal`。正式入口必须有位于作品根之外、哈希固定的操作员交接回执，包含已验收试验、源归档/版本、原端冻结及唯一执行者的证据字段；这些字段是操作员核验记录，不是平台独立认证。工具参数不能指定任意根目录、命令、注册表、作者决定或规则文件。
- `adopt_running_task` 仅供可信操作员使用，不在7个 MCP 工具中。对已核验冻结并恢复的 running 任务，生成 Dot 固定输入包并登记原任务，保留编号、attempts、no_progress 和全部原事件；不调用 claim/resume/cancel，不用新任务替代旧任务。过期、已停止、其他作品、存在其他未完成任务或重复登记时拒绝。第四章已通过该路径登记；原稿前三章未改。
- 每次修改使用请求 ID 和参数哈希。同一请求重放返回原回执，改参数会拒绝；不确定的中断不自动重跑。分段不可覆盖，遗漏片段、旧尝试、旧版本不能提交。无有效变更会保留 `no_progress` 停止状态。
- 审核与正文写入使用不同任务和声明的执行上下文。上下文 ID 是执行者声明，不是独立身份认证；真实独立审稿必须另外回读 Dot 原生子代理的实际任务和结果，不能只看不同字符串。
- `result.json` 读取返回已保存的真实结果，便于跨会话恢复审稿发现；不会把通知回执自动标成用户已收到。

`adapters/prepare_agent_hub_dot.py` 只对指定的 Hub 源码副本应用已核对的集成锚点，并检查 Python 语法；不部署、不改 OAuth 客户端或授权。锚点不匹配时拒绝继续。最终对原始选定源码的转换已复现线上两份源码哈希。

正式入口首次真实调用被 `NOVEL_CLIENT_DENIED` 拒绝：Hub 原实现验证 grant 后没有把 client_id 放入内部 principal。已补传该已验证 grant 的客户端身份，未移除绑定检查、修改 OAuth 数据库或 token；合成鉴权检查确认已验证客户端透传、撤销 grant 拒绝，随后真实正式状态/固定包调用成功。未登记工作区继续拒绝，旧 `task_bindings` 可用，Worker 未重启。相应备份及修正回执保留在 `client-identity-fix-receipt.json`。
